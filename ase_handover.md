# Pixel Effect Maker Handover

Current checkpoint targets v0.0.10 / project format v12. Resource `CompositionLayer.parent_id` and logical `EffectResourceLayer.parent_id` are the stable-ID Parenting sources of truth; Generated Effect layers do not duplicate the relation. Format v11 loads with no parent and is only written as v12 on an explicit save. Missing/self/cyclic links are repaired deterministically in memory without automatic save.

Hierarchy UX is a pure view layer shared by the Resource Composition Timeline and Effect Resource Layer list. Group membership alone controls indentation and disclosure; Transform Parenting remains a stable-ID relation displayed in a separate `[P: name]` badge. Duplicate names prefer `Group / Layer` paths and fall back to a short stable ID. Primary and additional selection markers, Visibility, own/inherited Group Lock, Solo, empty Groups, and full-name tooltips are derived from the model on each refresh without adding serialized state.

Hierarchy drag feedback classifies Group rows into Before / Into / After zones and Leaf rows into Before / After. The indicator resolves the same target parent and batch insertion index used by existing hierarchy mutation entry points; nested Groups, locked structural targets, and mixed-parent drags remain rejected. Expand All / Collapse All and disclosure state are runtime-only and reuse the existing collapse selection repair policy.

Editor density uses shared runtime-only layout metrics. Resource defaults to a 205 px browser, 320 px Inspector and 235 px Timeline; Effect defaults to a 250 px library and 340 px Inspector. Both Timeline hierarchy/name lanes use 220 px. Side panels have protected readable minima while the central Canvas remains the splitter's only expanding column. Existing valid splitter preferences are retained; saved layouts below the new readable minima fall back to these defaults. No project data, serialization, render, transform, selection or Undo semantics depend on these metrics.

Multi-Transform is runtime coordination over the existing single-layer transform paths. The Selection Pivot is the center of the World AABB of all selected Leaf transform origins at the current playhead and is frozen for a Canvas gesture. `get_selected_transform_roots` removes every selected descendant whose ancestor is also selected, preventing Parent+Child double transforms and duplicate Auto-Keys. Move applies one World delta and converts each root through its own Parent inverse. Rotation moves root origins around the frozen pivot and adds continuous Local Rotation Z; Scale moves origins around the pivot and multiplies Local Scale X/Y. Neither operation decomposes arbitrary affine matrices or creates shear, and `parent_id` / `parent_offset` remain unchanged.

Canvas gestures are World-space; Inspector batch edits are absolute Local-space and intentionally update every selected Leaf, including a selected Parent and Child. Mixed Position X/Y, Rotation Z and Scale X/Y use a 1e-6 comparison tolerance and display `—`. Existing conditional Auto-Key semantics are reused per layer. One gesture or numeric commit stores one focused batch Undo command; selection state is not modified by Undo/Redo. Group selections and selections containing any effectively locked Leaf are rejected atomically.

The automated 100-Leaf smoke fixture contains 50 parented leaves, a depth-50 chain and 10 groups. On the 2026-08-14 checkpoint run, model-side timings were Pivot 3.220 ms, Move 0.234 ms, Rotate 0.283 ms, Scale 0.253 ms and Undo payload capture 0.009 ms. Gesture updates do not serialize, reload or access the filesystem; full Windows visual/DPI interaction remains manual QA.

Parent world resolution memoizes one 3×3 affine per leaf and frame pass. Inherited components are Position X/Y, Rotation Z and Scale X/Y. Rotation X/Y, Position Z and Perspective remain local visual deformation because the current decomposed 2.5D raster projection cannot exactly compose arbitrary parent 3D transforms. Opacity, visibility, Solo, lock, playback speed, Local Z, Surface Transform, particle spawn/motion and Group membership/order are not inherited.

Set, Clear and Reparent serialize a maintain-world `parent_offset = inverse(new_parent_world) × old_world × inverse(child_local)` at the current playhead, preserving all existing tracks. Cycle checks run both in candidate UI and mutation entry points. Duplicate remaps parent references only when both endpoints are duplicated; dependent parent deletion is rejected unless every dependent child is in the same delete batch. Groups remain organization-only and have no Parent or Transform fields.

Resource and Effect editors keep runtime-only `selected_ids`, `primary_id`, `anchor_id`, and collapse state; none are serialized. Resource selection uses `CompositionLayer.id`. Effect selection uses logical `EffectResourceLayer.id`, with Generated Timeline rows mapped through `generated_layer_id`. Group Visibility affects preview and final output, Group Solo is preview-only, and Group Lock is inherited edit protection without changing child flags.

Leaf Lock guards model mutation entry points and permits selection, visibility, Solo, unlock, inspection, and exact-state duplicate. Leaf Solo uses `visible AND (no solo active OR solo)` only in editor Canvas/playback paths; final render, PNG, sequence, and Bake retain Visibility-only semantics.

Click/Ctrl+Click/Shift+Click and focus-scoped Ctrl+A do not enter Undo history or touch composition revision. Batch Duplicate, reorder, Delete, Lock, Solo, Visibility, Front and Back each use one existing editor Undo command containing before/after selection snapshots. Any locked selected layer rejects structural reorder/delete atomically; duplicate, Solo, Visibility, Lock and Unlock remain allowed. Multi-Transform supports Position X/Y, Rotation Z and Scale X/Y; Position Z, Rotation X/Y, Perspective, Opacity, Surface, particle/motion and playback properties remain Primary-only.

Layer Group Create/Ungroup/Move/Duplicate/Delete preserve flattened back-to-front order. Structural changes reject a locked group or locked descendant atomically. Collapse/expand is runtime-only. Empty groups remain valid save/reload and drop targets.
